# 귀여운 패싸움 전투 개편 설계

## 목표

현재의 차징 배치기 중심 전투를 유지보수가 쉬운 서버 권위형 근접 난투로 바꾼다. 기본 게임 규칙은 그대로 둔다.

- 최대 10명이 원형 아레나에서 싸운다.
- 아레나 밖으로 밀려나면 탈락한다.
- 캐릭터는 귀엽고 말랑한 3D 콩 캐릭터를 유지한다.
- 전투는 주먹 버튼과 킥 버튼만 사용한다. 실제 기술은 거리, 각도, 이동 포즈에 따라 자동 선택되어 실제 싸움처럼 읽히되 폭력성은 낮고 우스꽝스럽게 보이게 한다.

핵심 감성은 "Fall Guys 같은 캐릭터들이 Gang Beasts처럼 뒤엉켜 싸우는 점심시간 난투"다.

## 디자인 원칙

1. 판정은 단순하고 읽히게 만든다.
   - 실제 격투 시뮬레이션이 아니라 모바일 난투용 아케이드 판정.
   - 공격마다 선딜, 유효 프레임, 후딜, 범위, 각도, 넉백만 명확히 둔다.

2. 목적은 체력 깎기가 아니라 낙사 유도다.
   - HP를 넣더라도 보조 지표로만 사용한다.
   - 핵심 보상은 상대를 좋은 방향으로 때려서 밀어내는 위치 싸움이다.

3. 캐릭터 연출은 과장한다.
   - 팔/다리가 순간적으로 늘어나고 몸이 찌그러지는 squash/stretch를 적극 사용한다.
   - 피격 시 표정, 몸 눌림, 짧은 스턴, 통통 튀는 넉백을 강조한다.

4. 10명 난전에서도 가독성이 있어야 한다.
   - 공격 이펙트는 짧고 방향성이 있어야 한다.
   - 내 캐릭터, 피격자, 강한 킥 히트는 즉시 눈에 띄어야 한다.

## 전투 모델

### 플레이어 전투 상태

서버의 플레이어 상태에 아래 필드를 추가한다.

```js
combatState: 'idle' | 'straight' | 'hook' | 'frontKick' | 'roundKick' | 'dodge' | 'hitstun',
combatTicks: 0,
combatFrame: 0,
attackId: 0,
attackType: null,
attackFamily: null,
attackDirX: 1,
attackDirY: 0,
hitstunTicks: 0,
guarding: false,
hitReactX: 0,
hitReactY: 0,
hitReactTicks: 0,
hitTargets: new Set(),
```

클라이언트에는 `hitTargets`를 보내지 않는다. 브로드캐스트에는 렌더링에 필요한 값만 포함한다.

```js
combatState,
combatFrame,
attackType,
attackFamily,
attackDirX,
attackDirY,
hitReactX,
hitReactY,
hitReactTicks,
guarding,
```

### 공격 데이터

플레이어가 직접 고르는 입력은 `punch`, `kick` 두 종류다. 서버는 공격 시작 순간에 주변 상황을 보고 실제 기술을 고른다.

```js
const ATTACKS = {
  straight: {
    startup: 5,
    active: 4,
    recovery: 10,
    range: 72,
    arc: 0.55,
    knockback: 16,
    selfSlow: 0.65,
    hitstun: 10,
  },
  hook: {
    startup: 8,
    active: 6,
    recovery: 16,
    range: 64,
    arc: 1.9,
    knockback: 23,
    selfSlow: 0.5,
    hitstun: 14,
  },
  frontKick: {
    startup: 12,
    active: 5,
    recovery: 22,
    range: 98,
    arc: 0.65,
    knockback: 34,
    selfSlow: 0.35,
    hitstun: 18,
    whiffSlide: 3,
  },
  roundKick: {
    startup: 14,
    active: 7,
    recovery: 24,
    range: 78,
    arc: 1.55,
    knockback: 29,
    selfSlow: 0.35,
    hitstun: 18,
    whiffSlide: 2,
  },
};
```

수치 의도:

- 스트레이트: 빠른 견제. 뭉친 곳에서 계속 밀어내기 좋다.
- 훅: 가까이 붙었거나 옆으로 비비는 상황에서 자동 선택되는 난전용 주먹. 여러 명을 맞힐 수 있지만 느리다.
- 앞차기: 정면에 조금 떨어진 타겟이 있을 때 자동 선택되는 링 아웃 결정타. 강하지만 선딜/후딜이 길어 헛치면 위험하다.
- 돌려차기: 주변에 여러 명이 붙었거나 이동 방향과 조준 방향이 크게 어긋난 상황에서 자동 선택되는 광역 킥.

### 자동 기술 선택

서버는 입력을 받을 때 공격군별로 기술을 고른다.

```js
socket.emit('attack', { family: 'punch' | 'kick' });
```

선택 기준은 결정론적으로 유지한다.

주먹:

- 정면 75도 이내, 거리 70 이상인 가장 가까운 타겟이 있으면 `straight`
- 거리 70 미만의 타겟이 있거나 좌/우 120도 이내에 타겟이 2명 이상이면 `hook`
- 타겟이 없으면 이동 입력이 크면 `straight`, 정지 상태면 `hook`

킥:

- 정면 60도 이내, 거리 70 이상인 타겟이 있으면 `frontKick`
- 근거리 또는 측면에 타겟이 2명 이상이면 `roundKick`
- 타겟이 없으면 이동 입력 방향이 뚜렷하면 `frontKick`, 아니면 `roundKick`

이 방식의 장점:

- 모바일 UI는 두 버튼으로 단순하다.
- 플레이어는 "주먹/발"만 고르지만 캐릭터는 상황에 맞게 다양하게 싸운다.
- 10명 난전에서 기술 선택을 잘못 눌러서 답답한 순간이 줄어든다.

### 히트 판정

서버는 매 틱 공격 상태를 진행한다.

1. `startup`: 공격 준비. 아직 히트 없음.
2. `active`: 범위/각도 안의 상대를 판정한다.
3. `recovery`: 공격 후 빈틈. 새 공격/가드 불가, 이동 둔화.

타겟 판정:

- 공격자와 타겟의 거리 `dist <= attack.range + target.radius`
- 공격 방향과 타겟 방향의 각도 차이가 `attack.arc / 2` 이하
- 타겟이 이미 해당 `attackId`에 맞았으면 중복 히트 금지
- 타겟이 회피 무적이면 무시
- 타겟이 회피 중이면 무시

### 넉백과 히트스턴

피격자는 공격 방향으로 밀린다.

```js
target.vx += nx * knockback;
target.vy += ny * knockback;
target.hitstunTicks = Math.max(target.hitstunTicks, attack.hitstun);
target.hitReactX = nx;
target.hitReactY = ny;
target.hitReactTicks = 12;
```

hitstun 중에는 이동 입력 반영을 줄인다.

- 일반 이동 입력: 25%만 반영
- 공격 시작 불가
- 회피는 1차 구현에서는 불가

## 입력 설계

### 모바일 1차안

- 왼쪽: 이동 조이스틱 유지
- 오른쪽:
  - 큰 버튼: 주먹
  - 보조 큰 버튼: 킥
  - 작은 버튼: 회피

키보드는 1차 대상에서 제외한다. 이 게임은 모바일 전용 조작감을 우선으로 튜닝한다.

## 서버 이벤트

기존 `punch-start`, `punch-release`, `dash`는 제거 대상이다. 마이그레이션 중에는 호환용으로 남길 수 있지만 UI에서는 사용하지 않는다.

```js
socket.emit('attack', { family: 'punch' | 'kick' });
socket.emit('dodge');
```

서버는 유효하지 않은 입력을 조용히 무시한다.

- 죽은 플레이어
- 게임 중이 아님
- hitstun/recovery 중 공격 입력
- 알 수 없는 공격군
- 입력 레이트 초과

## 클라이언트 3D 연출

### 공통

캐릭터는 현재 primitive 조합을 유지한다. 복잡한 본 애니메이션 대신 파츠 위치/회전/스케일로 처리한다.

렌더러는 `combatState`, `attackFamily`, `attackType`, `combatFrame`, `hitReact*`를 보고 애니메이션을 만든다.

### 스트레이트

느낌: 짧은 팔이 순간적으로 쭉 나가는 귀여운 잽.

- 몸이 공격 방향으로 살짝 기울어짐
- 한쪽 팔/손이 앞으로 늘어남
- 손 끝에 작은 흰색/노란색 히트 스파크
- 헛치면 작은 바람선만 표시

### 훅

느낌: 몸 전체가 팽이처럼 돌며 옆으로 휘두름.

- 몸통 `rotation.y` 빠르게 회전
- 양팔이 바깥쪽으로 퍼짐
- 원호 형태의 짧은 스윙 이펙트
- 여러 명을 맞히면 "우당탕" 느낌의 다중 스파크

### 앞차기

느낌: 짧은 다리가 말도 안 되게 뻗는 결정타.

- 한쪽 다리/발이 앞으로 길게 스케일
- 몸은 뒤로 젖혀짐
- 맞은 쪽에 강한 충격파와 큰 넉백
- 헛치면 공격자가 살짝 앞으로 미끄러져 빈틈을 보여줌

### 돌려차기

느낌: 균형이 약간 무너진 채 한 바퀴 돌며 주변을 정리하는 우스꽝스러운 킥.

- 몸통이 크게 회전
- 한쪽 발이 옆으로 늘어나며 원호를 그림
- 여러 명을 맞히면 작은 별/먼지 이펙트를 여러 방향으로 표시
- 후딜 중 몸이 살짝 휘청거림

### 피격

피격 연출이 가장 중요하다.

- 몸이 맞은 방향 반대로 눌림
- 눈은 X 또는 크게 뜬 표정
- 입은 벌어짐
- 0.2초 동안 찌그러졌다가 복구
- 강한 킥 피격 시 바닥에서 한 번 통통 튀는 느낌

## 이펙트 방향

폭력성은 낮춘다.

- 피/상처 없음
- 별, 땀방울, 충격선, 작은 말풍선 느낌
- 강한 히트는 화면 플래시보다 캐릭터 리액션과 카메라 미세 흔들림 중심
- 킥 링아웃 직전에는 짧은 슬로모션 느낌을 검토할 수 있다. 서버 틱은 그대로 두고 클라이언트 연출만 늘린다.

## 1차 구현 단계

### Phase 1: 서버 전투 코어

- `server/mechanics.js`에 `ATTACKS`, `chooseAttackType()`, `calcAttackHits()` 추가
- `server.js` 플레이어 상태에 combat 필드 추가
- `attack` 이벤트 추가
- 틱 루프에서 공격 상태 진행 및 active 프레임 히트 처리
- 기존 배치기는 임시 호환만 유지하거나 비활성화
- 유닛 테스트 추가

성공 기준:

- 주먹 입력이 스트레이트/훅 중 하나를 자동 선택한다.
- 킥 입력이 앞차기/돌려차기 중 하나를 자동 선택한다.
- 한 공격으로 같은 타겟을 여러 번 때리지 않는다.
- 회피/죽은 플레이어 예외가 통과한다.

### Phase 2: UI 입력

- HTML에 주먹, 킥, 회피 버튼 추가
- `network.js`에 `sendAttack(family)` 추가
- `game.js` 입력 바인딩 변경
- 버튼 쿨다운/후딜 상태를 간단히 시각화

성공 기준:

- 모바일에서 주먹/킥/회피를 의도대로 누를 수 있다.
- 버튼 수가 적어서 엄지 조작이 안정적이다.

### Phase 3: 3D 캐릭터 애니메이션

- `animateCharacter()`에 combat 상태별 분기 추가
- 스트레이트/훅/앞차기/돌려차기/피격 포즈 구현
- 히트 이펙트 타입별 분리
- 내 캐릭터 가독성 유지

성공 기준:

- 멀리서도 주먹 계열과 킥 계열, 그리고 실제 선택된 기술이 구분된다.
- 피격 순간이 명확하고 우스꽝스럽다.

### Phase 4: 튜닝

- 봇 AI가 새 공격을 사용하도록 변경
- 10명 솔로 AI 난전에서 너무 빨리 끝나지 않게 수치 조정
- 아레나 수축/넉백/마찰 재튜닝
- 필요 시 킥 쿨다운 또는 스태미나 추가

## 리스크와 대응

1. 10명 난전에서 화면이 복잡해질 수 있다.
   - 공격 이펙트를 짧게 유지하고 색/크기를 타입별로 제한한다.

2. 앞차기가 너무 강하면 게임이 킥 원툴이 된다.
   - 선딜/후딜을 길게 두고, 헛치면 미끄러지는 리스크를 준다.

3. 자동 기술 선택이 예측 불가능하면 답답할 수 있다.
   - 기준을 거리/각도로 단순하게 유지하고, 버튼 피드백에 선택된 기술명을 짧게 보여주는 것을 검토한다.

4. 문서와 실제 렌더러가 다르다.
   - 이번 개편 때 프로젝트 문서의 "Canvas" 표현을 "Three.js/WebGL 렌더링"으로 갱신하는 것이 좋다.

## 추천 첫 구현 범위

가장 작은 재미 단위는 아래다.

- 스트레이트
- 훅
- 앞차기
- 돌려차기
- 피격 리액션
- 기존 회피 유지
- 가드와 키보드 조작은 보류

이 범위만으로도 "차징해서 터뜨리는 게임"에서 "귀여운 캐릭터들이 뒤엉켜 실제로 싸우는 게임"으로 체감이 크게 바뀐다.
